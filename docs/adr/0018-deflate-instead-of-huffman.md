# ADR 0018. Сжатие трафика стандартным deflate вместо таблицы Huffman UO

- **Статус:** предложено, 14 ноября 2026; пересмотрено в тот же день по замечанию пользователя («не ухудшать функциональность, а улучшать»). Код не менялся. **Отложено** до юридического этапа после переноса функционала (решение пользователя, 14 ноября 2026, см. `LEGAL.md`); до этого клиент работает с Huffman как есть.
- **Закрывает:** открытый вопрос A в [`LEGAL.md`](../LEGAL.md). **Уточняет:** `LICENSES.md` §1, [ADR 0013](0013-network-core.md) (сжатие на игровом сокете).
- **Первая редакция** («сервер не сжимает данные для нашего клиента») отклонена: убирала риск ценой роста трафика.

## Контекст
1. `Assets/TheVerge/Network/Compression/HuffmanTree.cs` — таблица кодов Huffman (32 строки), совпадающая с `Projects/Server/Network/NetworkCompression.cs` (GPL-3.0). Единственное настоящее совпадение с кодом сервера, найденное `tools/check/legal.sh`. Правило проекта: код ModernUO в клиент не переносится (`LICENSES.md` §1).
2. Сжатие UO слабое: таблица фиксированная, каждый байт кодируется отдельно, без памяти о прошлых данных. По комментарию в самом сервере — от 2/8 до 11/8 исходного размера, то есть часть байтов даже **раздувается**.
3. Трафик MMO сильно повторяется: одни и те же номера пакетов, серийные номера объектов, координаты, имена. Это лучше всего сжимает алгоритм, который помнит недавние данные — deflate (LZ77 + Huffman), потоком на всю сессию.
4. Deflate есть в стандартной библиотеке .NET (`System.IO.Compression`, MIT) и на сервере (.NET 10), и в Unity (netstandard2.1). Клиент уже пользуется им в `Data/Files/Zlib.cs`. Новых пакетов не нужно.

## Решение
1. **Наш клиент и сервер договариваются о сжатии deflate** (расширение протокола **E3** в `docs/protocol/extensions.md`): клиент объявляет при входе, что понимает deflate; сервер для такого клиента включает поток deflate на всю игровую сессию (одно состояние на соединение, «sync flush» в конце каждой отправки — клиент сразу получает всё отправленное, задержки нет).
2. **Клиент без объявления (ClassicUO для сверок) получает прежний Huffman** — сервер не меняет поведения для чужих клиентов, сверки идут без переключения настроек. Таблица Huffman остаётся только в сервере — там она по праву (GPL-сервер).
3. **Клиент:** удалить `HuffmanTree`, `HuffmanDecoder`, их тесты и `HuffmanTestEncoder`; вместо них — потоковая распаковка через стандартный `DeflateStream`. В клиенте нет ни строки чужой таблицы.
4. **Сервер:** правка в `UOContent` (где сейчас включается сжатие, `IncomingAccountPackets.GameLogin`) и минимально в `NetState` ядра — **только с разрешения пользователя** (`AGENTS.md` §5 п. 3), каждая строка — в `docs/server-patches.md` с пометкой `// THE VERGE:`.

## Как проверяем (до внедрения и после)
1. **Замер до внедрения** (решает, внедрять ли): на записанном настоящем трафике (`dotnet/TheVerge.Tests/Bot/Replays/*.tsv` и новая запись 10 минут игры ботом) сравнить размер: без сжатия / Huffman UO / deflate потоком. Внедряем, только если deflate меньше Huffman. Результат — таблицей сюда.
2. **Тесты клиента:** распаковка даёт те же пакеты при любой нарезке TCP (как было для Huffman); повреждённый поток — ошибка протокола, а не зависание.
3. **Проверка на сервере:** бот входит, играет и выходит с deflate; ClassicUO входит с Huffman.
4. **Цена на сервере:** память и процессор на соединение (у zlib со стандартными настройками — порядка сотен КБ на соединение на сжатие) — замерить на нагрузочном прогоне; при необходимости — уровень сжатия ниже.
5. `tools/check/legal.sh` не находит совпадений в `Network/Compression`; запись `copies` в `legal-baseline.json` удаляется.

## Почему так, а не иначе
- **Оставить таблицу, записав «константы протокола».** Риск меньше, но не ноль; критерий пользователя — ноль.
- **Выписать таблицу заново «из спецификации».** Значения обязаны совпасть побайтно — независимое происхождение не доказать.
- **Выбрать GPL-3.0 для клиента.** Лишает права закрыть клиент.
- **Не сжимать вовсе** (первая редакция). Риск ноль, но трафик растёт — ухудшение.
- **Deflate потоком** — риск ноль (стандартная библиотека, MIT) и ожидаемо меньший трафик, чем у Huffman UO; подтверждается замером п. 1.
