# ADR 0011. Аудит прототипа: решение по каждому файлу вместо «заменим потом»

- **Статус:** предложено, 11 ноября 2026 (задача 0.9, ждёт подтверждения пользователя)
- **Меняет:** `docs/TECH-DEBT.md` §1 («новый код пишется рядом, старые файлы удаляются, когда новый код их заменит; старое не переделывается»)

## Контекст

1. По `TECH-DEBT.md` §1 прототип (`Assets/TheVerge`, ~7 200 строк) жил рядом с новым кодом, пока его не заменят Стадии 1–8. Значит, неделями в проекте были бы две архитектуры сразу. Агенты видят старые образцы (фасады, диспетчер потоков, UI из C#) и повторяют их.
2. Бо́льшая часть прототипа уже не работает или никем не вызывается: симулятор мира и меню Esc никто не создаёт; у фасадов движения, предметов и боя нет ни одного вызова из Unity; команды песочницы `[minoc:` на сервере выключены (ADR 0004). В Unity сейчас работают только окна входа и окно статуса сети.
3. Часть прототипа построена на правилах GDD (создание персонажа: 80 очков статов, навыки 50/50/10, «вечные» стартовые наборы), а GDD отменён (ADR 0001); сервер требует сумму статов 90 и навыков 100 или 120 (`TARGET.md` §4).
4. Ценные куски (распаковка Huffman, номера шагов, базовые типы) лежат без тестов и не в своих папках.
5. Замороженный прототип держит базовую линию проверок большой: 75 нарушений и 8 предупреждений (ADR 0009).

## Решение

1. **У каждого файла `Assets/TheVerge` одно из трёх решений** (таблица ниже): удалить; оставить и довести; оставить как есть.
2. **Удаляем сразу**, не дожидаясь замены, всё, что противоречит `AGENTS.md` (фасады-адаптеры, диспетчер главного потока, UI из C# на uGUI), серверу (правила GDD, выдуманные имена и числа по умолчанию) или дублирует сервер (симулятор мира, учебный сервер, захардкоженный кусок карты).
3. **Оставляем и доводим** то, что совпадает с сервером и нужно плану. Порядок (ADR 0010 п. 5): тест на текущее поведение с ожиданиями из исходника сервера → если код расходится с сервером, тест пишется на поведение сервера и код исправляется → перенос в правильную папку и чистка под `AGENTS.md` §3 при зелёных тестах.
4. **Код удаляемых файлов не служит образцом.** Новые обработчики пакетов пишутся по исходнику сервера (ADR 0010 п. 3), а не переносом старого разбора.
5. **Порядок — по слоям, от Unity к Core** (так каждое удаление убирает потребителей следующего слоя). Каждая часть — отдельный коммит; после каждой `tools/check/all.sh` зелёный, базовые линии только уменьшаются.
6. **Зависимости сборок:** из `TheVerge.Presentation.asmdef` убираются ссылки на `UnityEngine.UI` и `Unity.TextMeshPro`, из `TheVerge.Editor.asmdef` — на `Unity.TextMeshPro` и `Unity.TextMeshPro.Editor` (новый UI — только UI Toolkit, ADR 0007). Сами пакеты в `manifest.json` пока остаются (`TECH-DEBT.md` §2).
7. **В пустой сборке Presentation** остаётся тип-метка `PresentationAssembly` — так же, как `DataAssembly` в сборке Data (без скриптов Unity не собирает сборку из `.asmdef`).
8. `TECH-DEBT.md` §1 заменяется ссылкой на этот ADR и списком того, что осталось. Правило `AGENTS.md` §8 (долг замораживается, бойскаут) остаётся для будущего долга.

## Последствия

- Базовые линии: `architecture-baseline.txt` 75 → 0, `dotnet-warnings-baseline.txt` 8 → 0; пометки `#nullable disable` исчезают вместе с файлами.
- **В Unity до задачи 1.16 нет окна входа:** Play показывает пустую сцену и строку в Console. Вход проверяется ботом и тестами Стадии 1.
- В `PROGRESS.md` статус «прототип» (🟨) у Стадий 1–6 меняется на «не начато» (⬜), с пометкой, какие куски остались (Huffman, очередь шагов, базовые типы).
- В `PLAN.md` нет задачи на создание и удаление персонажа, хотя `TARGET.md` §4 их описывает: добавляется в Стадию 1 (п. 8 — пакеты 0xF8, 0x83 → 0x85; п. 16 — окно в Unity).
- Сервер не меняется. Песочница Минока и перехваты `[minoc:` остаются долгом сервера (`TECH-DEBT.md` §3): клиент их больше не вызывает.
