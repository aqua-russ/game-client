# ADR 0008. Уточнения архитектуры клиента: порты отправки, сборка Data, Bootstrap

- **Статус:** принято, 10 ноября 2026 (по итогам второго аудита документов)

## Контекст
В `AGENTS.md` оставались три неясности, которые агент решал бы каждый раз по-своему:
1. «Команда в Core пишет пакет через `IPacketSink`». Но классы пакетов лежат в Network, а Core на Network ссылаться не может. Получалось либо собирать байты в Core, либо делать один интерфейс на сотню методов.
2. Не было сказано, где живёт чтение файлов данных UO (карта, статика, tiledata, multi, cliloc). Это большой отдельный код со своими форматами (MUL, UOP).
3. Сборка `Bootstrap` описана, но в проекте её ещё нет: `Presentation` пока ссылается на `Network`.

## Решение
1. **Порты отправки по доменам.** В `Core/Ports` для каждого домена — маленький интерфейс `I<Domain>Sender` (не больше 7 методов): `IMovementSender`, `ICombatSender`, `IItemSender` и т.д. Команды Core вызывают порт своего домена. Реализации (`MovementSender` …) лежат в `Network/Packets/<Domain>/` и пишут `*Packet`. В Core нет id пакетов и байтов. Общего `IPacketSink` в Core нет.
2. **Сборка `TheVerge.Data`** (чистый C#, ссылается только на Core): чтение файлов UO. Core описывает, что ему нужно, интерфейсами `IMapData`, `ITileData`, `IMultiData`, `IClilocData` в `Core/Ports`; Data их реализует. Проверка шага и мир в тестах работают на карте из памяти, без файлов.
3. **Сборка `TheVerge.Bootstrap`** создаётся в задаче 0.1; тогда же убирается ссылка `Presentation → Network`.
4. **Отправка — один раз в конце тика.** Исходящие пакеты копятся в буфере и уходят в сокет в конце `GameClient.Tick`; главный поток на сокете не блокируется.
5. **Nullable — на уровне сборки** (`csc.rsp` рядом с `.asmdef` + `<Nullable>enable</Nullable>` в `.csproj`), а не строкой в каждом файле.
6. **Без DI-контейнера.** Объекты связывает `Bootstrap` конструкторами: зависимостей мало, а контейнер скрывает, кто от кого зависит.

## Последствия
- В `dotnet/` три проекта чистого кода (Core, Network, Data) плюс Tests и Bot.
- Бот использует те же Core, Network и Data, что и Unity; Presentation ему не нужна.
- Правило «Core без Unity» проверяет компилятор (`noEngineReferences`), а «Core без пакетов и файлов» — `tools/check/architecture.sh` (в Core запрещены `System.Net` и `System.IO.File`).
