# ADR 0006. Режим 3б (направление тела) через PlayerMobile, без правки движка

- **Статус:** принято как подход, 10 ноября 2026; реализация — Стадия 3б

## Контекст
Поворот или шаг решает `Mobile.Move` (движок, `Projects/Server/Mobiles/Mobile.cs`): если направление отличается, персонаж только поворачивается. Стоимость шага считает `PlayerMobile.ComputeMovementSpeed`, и при смене направления она равна `TurnDelay` = 0. `MovementThrottle` вызывает её **до** `Move`. Если просто разрешить «шаг в новом направлении сразу», каждый такой шаг будет бесплатным — это спидхак.

## Решение
Всё в `Projects/UOContent`, движок не трогаем:
1. Флаг расширения Facing приходит при входе; хранится в состоянии сессии.
2. `PlayerMobile.Move` (уже виртуальный и переопределён) для сессий с флагом выставляет направление движения до `base.Move`, чтобы шаг шёл сразу.
3. `PlayerMobile.ComputeMovementSpeed` для таких сессий не возвращает `TurnDelay`: стоимость шага всегда обычная.
4. `Facing` — отдельное поле `PlayerMobile`; `Direction` остаётся направлением движения.
5. Пакет «направление тела» от клиента — свободная подкоманда 0xBF через `IncomingExtendedCommandPackets.RegisterExtended`; рассылка соседям — своим пакетом. Описание — в `protocol/extensions.md` до кода.

## Риски
AI, стрельба, каст и `GetDirectionTo` читают `Direction`; каждое место явно решает, нужно ли ему направление движения или тела.
