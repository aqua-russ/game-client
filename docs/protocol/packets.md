# Матрица пакетов: как читать и как менять

[`packets.csv`](packets.csv) — единственный список пакетов протокола для клиента 7.0.95.0 и эры Renaissance: номер, подкоманда, направление, длина, нужен ли пакет клиенту. Этот файл объясняет его столбцы и правила; сами пакеты описаны только в CSV.

**Источник правды — исходник сервера ModernUO** (путь в столбце `source`). Справочник modernuo.com/packets.html — только подсказка: расходится с исходником — прав исходник.

## Что в матрице

- Строка на каждый пакет и каждую подкоманду, которые есть в исходнике сервера, отдельно для каждого направления. Пакеты, у которых в сервере есть код, но нет вызовов, тоже записаны (статус «не используется»): если такой пакет всё же придёт, клиент знает его длину.
- **Пакетов, которых в сервере нет совсем** (например 0x8D, 0xAB, 0xAC, 0xB0, 0xD2, 0xD3, 0xE3, 0xBF 0x33), в матрице нет. Клиент их не реализует; при приёме таблица отвечает «неизвестен», и клиент делает контролируемый дисконнект с дампом (`AGENTS.md` §3.5).
- **Подкоманды** записаны у пакетов 0xBF (2 байта сразу после длины), 0xD7 (2 байта после serial), 0x12, 0xF0 и 0xF1 (1 байт после длины). У такого пакета есть ещё общая строка без подкоманды: по ней поток режется на пакеты, её длина — `var`.

## Столбцы

| Столбец | Что значит | Значения |
|---|---|---|
| `id` | номер пакета | `0x00`–`0xFF` |
| `sub` | подкоманда | пусто или `0x00`–`0xFF` |
| `dir` | кто шлёт | `c2s` — клиент серверу, `s2c` — сервер клиенту |
| `name` | имя по смыслу UO/ModernUO, для логов и кода (`AGENTS.md` §3.3) | латиница, PascalCase; в одном направлении не повторяется |
| `length` | длина пакета целиком для нашей версии | число байт или `var` — после номера идут 2 байта длины |
| `condition` | от чего зависит длина или формат: версия клиента (флаги `ProtocolChanges`), эра, настройка сервера | свободный текст |
| `server` | шлёт ли сервер этот пакет (`s2c`) или обрабатывает ли его (`c2s`) в нашей конфигурации | `да`; `нет` — никогда (нет вызовов, другая версия или эра); `настройка` — только при включённой настройке (какой — в `condition`), по умолчанию выключена; `игнорирует` — пакет клиента сервер читает и ничего не делает |
| `priority` | важность для клиента | `P0` — без него нет входа, мира и шага; `P1` — основная игра: речь, статус, бой, предметы, прицел, гампы и меню крафта; `P2` — остальное из Стадий 0–8; `P3` — редкое; `-` — не нужен |
| `stage` | задача плана, где пакет реализуется | `стадия.задача` из `PLAN.md` (`2.9а`), `-` — нет в плане |
| `status` | что делаем | `нужно` — реализуем в указанной задаче; `отложено` — сервер может прислать, но в плане Стадий 0–8 этого нет; `не используется` — клиенту не нужно |
| `source` | где пакет в исходнике сервера | путь от `server/ModernUO` и метод: `Projects/…/Файл.cs#Метод`; `-` только у общей строки пакета с подкомандами, у которой нет одного места в сервере |
| `note` | пояснение | свободный текст |

В полях нельзя писать запятые и кавычки (вместо запятой — `;` или `—`): так файл читается просто и без ошибок разбора.

## Правила (проверяет `tools/check/packets.sh`, входит в `tools/check/all.sh`)

- Заголовок и 12 полей в каждой строке; значения только из таблицы выше.
- Строка «номер + подкоманда + направление» не повторяется.
- `server` = `нет` → `status` = `не используется`; `игнорирует` — только у `c2s`.
- `нужно` → есть приоритет и стадия; `отложено` → есть приоритет; `не используется` → приоритет и стадия `-`.
- У пакета с подкомандами есть общая строка; у неё и у подкоманд длина `var`; её статус и приоритет — лучшие среди подкоманд.
- Строки отсортированы: номер, затем `c2s` и `s2c`, затем подкоманда (общая строка первой).
- Файл и метод из `source` есть в `server/ModernUO` (если папка сервера рядом).
- Сама проверка перед каждым запуском прогоняет себя на заведомо испорченных примерах.

## Как изменить строку

1. Найти пакет в исходнике сервера: где искать — [`SERVER-MAP.md`](../SERVER-MAP.md) §2.
2. Поправить или добавить строку в `packets.csv`, сохранив порядок строк.
3. Запустить `tools/check/packets.sh` — должно быть `ОК`.

При обновлении ModernUO матрица сверяется с исходником заново (`PLAN.md` §13).
