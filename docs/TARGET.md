# TARGET — цель клиента и сервера

Единственный источник конкретных значений протокола и правил. Код клиента берёт их из одного класса `ServerLimits`, этот файл — их документ. Меняется только через ADR.

*Обновлено 15 ноября 2026 (§2 и §3.2: что в контекстных меню UOR, известность торговцев, группа, бросок вещи на моба, команда двери, стены и поля, поверхности добычи, одиночный клик — для [ADR 0022](adr/0022-mouse-camera-targeting.md)). Ранее — 13 ноября 2026 (задачи 1.8–1.15: флаги карт клиента, правила создания персонажа, значения сессии — [ADR 0016](adr/0016-login-and-session.md)). Ранее — 12 ноября 2026 (задачи 1.12, 1.15: §3.1 — лог пакетов и бот; §5 — ручной список исключений и молчаливое подключение). Каждая строка проверена по исходникам `server/ModernUO`; где искать — [`SERVER-MAP.md`](SERVER-MAP.md). Список пакетов с длинами и статусами — [`protocol/packets.csv`](protocol/packets.csv); эта страница — версия, эра, лимиты и стенд.*

## 2. Пакеты и эра

Какие пакеты сервер шлёт и принимает для 7.0.95.0, их длины, зависимость от версии клиента и что из этого нужно клиенту — [`protocol/packets.csv`](protocol/packets.csv) (столбцы `server` и `status`; как читать — [`protocol/packets.md`](protocol/packets.md)).

**Что эра UOR включает и выключает** (проверено по коду):

| Возможность | В UOR | Откуда |
|---|---|---|
| Оглушение и обезоруживание (0xBF 0x09, 0x0A) | **работают** только в UOR и раньше AoS | `Items/Weapons/Fists.cs` |
| Каст 0xBF 0x1C | работает в любой эре | `IncomingExtendedCommandPackets.CastSpell` |
| Контекстные меню (0xBF 0x13 → 0x14 → 0x15) | работают в любой эре. Человеку (и призраку) сервер всегда добавляет «Кукла». Меню другого игрока в UOR — только «Кукла»: «Обмен» — с эры TOL, «В группу» и «Исключить из группы» — с AoS. Меню торговца (купить, продать), банкира (банк), питомца (команды, вьюк) и «Приручить», «Учиться» — в любой эре. **Решено изменить** ([ADR 0022](adr/0022-mouse-camera-targeting.md), Стадия 7): «Обмен» и пункты группы в меню игрока — и в UOR | `Context Menus/ContextMenuSystem.cs`, `PlayerMobile.GetContextMenuEntries`, `BaseVendor`, `Banker`, `BaseCreature.GetContextMenuEntries` |
| Группа (0xBF 0x06) | работает в любой эре: «добавить» открывает прицел сервера «кого пригласить», «исключить» берёт serial из пакета | `IncomingExtendedCommandPackets.PartyMessage`, `PartyCommands.cs` |
| Торговцы и банкиры | в UOR **смертны и синие**, как игроки: неуязвимость по умолчанию только с эры LBR (`vendor.isInvulnerable`), жёлтая известность «неуязвимый» — только с AoS. Чужие питомцы тоже синие; свой питомец помечен в статусе 0x11 «можно переименовать». Признака «это игрок» в пакетах моба нет — игрока от NPC клиент не отличит | `BaseVendor` (`_vendorInvulnerable`), `Notoriety.MobileNotoriety`, `Mobile.GetPacketFlags`, `BaseCreature.CanBeRenamedBy` |
| Кнопка гильдии на кукле (0xD7 0x28) | **ничего не делает**: новая система гильдий только с SE; гильдии — через камень гильдии и гампы | `Misc/Guild.cs` (`NewGuildSystem => Core.SE`) |
| Кнопка квестов (0xD7 0x32) | квестов ML нет (`questSystem.enableMLQuests` = False) | `modernuo.json` |
| Крафт и инструменты | меню 0x7C / 0x7D: двойной клик по инструменту → прицел (в инструмент — «сделать последнее», в материал — меню) → меню; у писаря и картографа инструмента нет. В руку надеваются только молот кузнеца и кувалда, кирка (одна рука), топор и удочка (обе руки) | `t2aCraftMenus` (по умолчанию включён до UOTD), `BaseTool.cs`, `SmithHammer.cs`. **Решено изменить** ([ADR 0021](adr/0021-tools-in-hand-craft-window-stance.md)): одно окно ремесла 0xDD / 0xB1 (`t2aCraftMenus = false`, Стадия 6) и все инструменты в руке (Стадия 5) |
| Тултипы, баффы, спецприёмы оружия, конструктор домов, плавный ход кораблей, золото на счёте | выключены. **Решено изменить** ([ADR 0024](adr/0024-later-era-conveniences.md)): тултипы (`opl.enable`, Стадия 5), иконки эффектов (`buffIcons.enable`, Стадия 7) и числа урона (`visibleDamage`, Стадия 4) включаются настройкой; там же — список других удобств поздних эр, которые берём (зелья стопкой, рюкзак 550, книга рун, питомцы, гильдии и др.), и того, что оставляем как в UOR | `ExpansionConfiguration.cs`, `BuffInfo.cs`, `expansion.json` |
| Школы магии, кроме Magery (некромантия, рыцарство, бусидо, ниндзюцу, spellweaving, mysticism) | регистрируются только с AoS и позже | `UOContent/Spells/Initializer.cs` (`Core.AOS`, `Core.SE`, `Core.ML`, `Core.SA`) |
| Гаргульи, полёт (0xBF 0x32), смена расы (0xBF 0x2A) | эра SA — не реализуем | `IncomingExtendedCommandPackets.cs` |

| Шаг верхом: ходьба / бег | 200 / 100 мс | `movement.delay.walkMount` / `runMount` |
| Поворот на месте | 0 мс | `movement.delay.turn` |
| Sequence шага | первый 0, далее 1–255, после 255 → 1; отказ 0x21 сбрасывает в 0 | — |
| Кредит на джиттер | 200 мс + до 150 мс по RTT | `movementThrottle.maxCredit`, `maxRttBonus` |
| Очередь шагов на сервере | сброс при 10 | `movementThrottle.hardQueueLimit` |
| Подозрение / спидхак | темп выше на 5% / 10% | `movementThrottle.suspiciousRateThreshold` / `definiteRateThreshold` |
| Проверка темпа | только если включён флаг `speedhack_detection`, только для игроков | `FeatureFlags/flags.json` |
| Неподтверждённых шагов на клиенте | 3 (настройка клиента) | — |

| Переименование 0x75 | не чаще 500 мс | `throttles.json` |
| Задержка действий | 500 мс; действует на 0x06, 0x07 (подъём) и 0xBF 0x2C, ответ прицела 0x6C ею не ограничен; раньше срока сервер отвечает «подождите» | `actionDelay` (по умолчанию для pre-AoS); `IncomingEntityPackets.UseReq`, `Mobile.Lift` |

### 3.1. Настройки клиента

Значения самого клиента, которых нет на сервере ([ADR 0013](adr/0013-network-core.md)). В коде — класс `ClientLimits`; предел длины пакета — `PacketInfo.MaxLength`.

| Что | Значение | Почему |
|---|---|---|
| Самый длинный пакет от сервера | 65 535 байт | столько вмещает поле длины (2 байта); отдельного предела у сервера нет (`PacketUtilities.cs`, `WritePacketLength`). Меньше заголовка (3 байта, у 0xBF — 5, у 0xF0 — 4) — ошибка |
| Дамп при ошибке нарезки | весь пакет; если длина неизвестна — до 256 байт с места ошибки | хватает, чтобы понять, что пришло, и лог не раздувается |
| Очередь пакетов от сокета к главному потоку | 2 МБ | как `network.sendBufferMaxSize` сервера (`NetState.Network.cs`): полная очередь останавливает чтение сокета, и сервер сам отключает клиента |
| Бюджет тика на разбор пакетов | 5 мс, но не меньше одного пакета за тик | треть кадра при 60 FPS; очередь движется, даже если пакет обрабатывается дольше |
| Таймаут подключения | 10 с | дольше сервер на локальном и обычном стенде не отвечает только при сбое |
| Предел файла лога пакетов | 64 МБ (`ClientLimits.PacketLogMaxChars`) | сессия входа — килобайты, часы в мире — единицы МБ; дальше запись останавливается строкой `#truncated`, файл на части не делится: одна сессия — один файл для фейкового сервера |
| Язык клиента (0xBF 0x0B после входа в мир) | ENU (`ClientLimits.Language`) | как у классического клиента по умолчанию; сервер пишет его в `Mobile.Language`, тексты cliloc выбирает сам клиент |
| Ping в мире (0x73) | раз в 10 с (`ClientLimits.PingIntervalMs`) | сервер отключает после 30 с без обмена данными (`NetState.Network.cs`: `NextActivityCheck`; `NetState.cs`, `CheckAlive`); треть предела переживёт два потерянных ping; ClassicUO (эталоны 0.6) шлёт раз в ~1 с — серверу всё равно, умолчание оставлено (`golden/allowed-diffs.md`) |
| Ожидание ответа на выход (0xD1) | 5 с (`ClientLimits.LogoutTimeoutMs`) | дальше клиент закрывает соединение сам |
| Цвет своей речи (0xAD) | 0x02B2 (`ClientLimits.SpeechHue`) | сервер приводит цвет к допустимому сам (`Utility.ClipDyedHue`); как у ClassicUO по умолчанию — сверено по эталону 0.6 (`golden/03-speech.tsv`): ClassicUO шлёт тот же цвет 0x02B2 и шрифт 3 |
| Очередь речи | до 16 фраз, по одной не чаще 25 мс (`SpeechCommands.QueueLimit`) | чаще сервер речь игрока отбрасывает (`throttles.json`) |
| Удаление объектов за дальностью обзора | включено (`ClientLimits.RemoveOutOfRange`): дальше 18 клеток, multi — 22, считая от своего персонажа, когда он сдвинулся | сервер за оставшимися позади 0x1D не шлёт (`Mobile.SetLocation`); выключать — только для отладки |
| Ожидание ответа сервера во время входа | 30 с (`ClientLimits.ServerResponseTimeoutMs`) | список шардов, редирект, список персонажей, вход и загрузка мира; дальше — ошибка `Timeout`, клиент не ждёт молча; пока выбирает человек — не считается |
| Повтор входа (не подключились, разрыв в мире) | паузы 1, 2, 4, 8, 16 с — 5 попыток, затем ошибка (`ClientLimits.ReconnectDelaysMs`) | тем же шардом и персонажем; отказы сервера и ошибки протокола не повторяются; в боте — только с `--reconnect` |
| Адрес сервера на экране входа по умолчанию | `127.0.0.1:2593` (`ClientLimits.DefaultServerAddress`) | локальный стенд; последний введённый адрес и логин Unity запоминает на этом компьютере, пароль — никогда ([ADR 0017](adr/0017-login-screens-unity.md)) |
| Размер журнала боя | 512 последних событий (`ClientLimits.CombatLogCapacity`) | замахи, анимации, урон, эффекты, звуки по пакетам сервера; полный — старое вытесняется, новой памяти не берёт; бой с крысой — около 45 событий за 20 с |
| Догонять опоздание шага | до 50 мс (`ClientLimits.MoveCatchUpMs`) | тик кадра или бота приходит позже срока шага; опоздание до 50 мс догоняется — следующий шаг идёт по расписанию, как считает сервер (`Mobile.Move`: `_nextMovementTime += cost`), поэтому темп не отстаёт (без этого бот с тиком 16 мс бегал бы на ~4% медленнее, верхом на ~8%); большее опоздание (игрок стоял) не копится — клиент не опережает расписание сервера и не тратит его запас на джиттер (`PLAN.md` §5, задача 7) |
| Догонялка картинки шага | не быстрее чем вдвое (`ClientLimits.StepCatchUpMaxSpeedup`) | отставшая на несколько клеток картинка показывает шаг быстрее, но не больше чем в 2 раза ([ADR 0020](adr/0020-movement-prediction-and-smoothing.md) п. 4; `StepTiming`) |
| Перескок картинки | при разрыве больше 2 клеток (`ClientLimits.StepSnapGapCells`) | дальше — не ехать, а сразу встать на клетку (ADR 0020 п. 5) |
| Ожидание второй клавиши движения | 50 мс перед первым шагом из покоя (`ClientLimits.MovePairWaitMs`) | пару клавиш (`W`+`D`) не нажимают ровно одновременно: без ожидания первый шаг ушёл бы прямо, а не по диагонали (`PLAN.md` §5, задача 1; `CONTROLS.md` §4); пара, нажатая раньше, уходит сразу |
| Бот: пауза между тиками | 16 мс (`BotRunner.TickIntervalMs`) | как кадр Unity при 60 FPS |
| Бот: файлов лога пакетов | 20 последних (`PacketLogFiles.KeepCount`) | `Logs/packets/`, не в git; старые бот удаляет сам |

## 4. Правила создания персонажа (ванильные, UOR)

- Имя: после обрезки пробелов по краям 2–24 символа, не больше 29 байт UTF-8, только буквы, пробел, дефис и апостроф (`NameVerification.cs`, `ValidatePlayerName`); иначе сервер молча назовёт персонажа «Generic Player».
- Статы: сумма **90** (для клиентов 7.0.16+), каждый 10–60.
- Навыки: **4** (клиенты 7.0.16+), каждый ≤ 50, сумма **100 или 120**, без повторов. Выбрать можно номера 0–46 (Alchemy … Meditation) и Mysticism (55): Stealth, RemoveTrap и Spellweaving сервер при создании не принимает, некромантию, Focus, рыцарство (до AoS), бусидо, ниндзюцу (до SE), Imbuing и Throwing (до SA) обнуляет (`CharacterCreation.cs`, `ValidateSkills`).
- Неверный выбор сервер не отвергает, а молча портит (статы 10/10/10, навыки пропадают, имя «Generic Player»), поэтому клиент такое не отправляет (`Core/Session/CharacterCreationRules`).
- Стартовый город — выбор из списка сервера (только Фелукка).
